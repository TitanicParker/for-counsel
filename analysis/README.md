# Analysis and audit index

This directory is for **project analysis, not primary evidence**.

The counsel-facing case must be reproducible from the primary records. Analytical documents may identify propositions, dependencies, questions and evidential gaps, but they do not prove the underlying facts merely by existing or by repeating each other.

## Controlling analytical sequence

The current revision was prepared from four supplied project files in the following order:

1. `impeached-hinge-case-build.md`
2. `dependency-severance-revalidation-audit.md`
3. `simt-source-architecture-revalidation-audit.md`
4. `../audit/source-provenance-documentary-legal-audit.html`

**Hierarchy:** the fourth file is the final quality-control / provenance / legal audit. Where it qualifies, corrects, downgrades, removes or reformulates anything in the earlier three, the final audit controls.

## Status of repository mirroring

The four controlling files were supplied to this revision as project inputs. The counsel overview links their intended repository paths so they remain separated from primary evidence. This branch adds the index and counsel rewrite first; a verbatim mirror of the supplied analytical files should preserve their text and provenance rather than silently rewrite them.

## Use rule

When an analytical phrase appears — for example “impeached hinge”, “dependency severance”, “recursive validation”, “institutional inheritance” or “temporal compression” — translate it back into the ordinary evidential proposition it is intended to describe. None of those expressions is presented as Irish legal doctrine.
